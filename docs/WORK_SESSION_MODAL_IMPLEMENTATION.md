### Core Features Implemented

#### 1. Modal-Based Work Session Tracking
- **Trigger**: Click anywhere on a todo card (except action buttons)
- **Display**: Modal dialog centered on screen with work session controls
- **Content**:
  - Todo title
  - Large timer display (HH:MM:SS format)
  - Dynamic button controls (Start/Pause/Resume/End)

#### 2. Timer Functionality
- **Initial State**: 00:00:00
- **While Running**: Updates every 1 second
- **Pause Behavior**: Timer stops counting but elapsed time preserved
- **Resume Behavior**: Timer resumes from paused time
- **Display Locations**:
  - Modal: Large 48px font, monospace, #667eea color
  - Floating Badge: Secondary timer for background reference

#### 3. Button State Machine
```
START STATE (Initial)
├─ [Start] → RUNNING STATE
│
RUNNING STATE
├─ [Pause] → PAUSED STATE
└─ [End] → CLOSE MODAL & MARK DONE

PAUSED STATE
├─ [Resume] → RUNNING STATE
└─ [End] → CLOSE MODAL & MARK DONE
```

#### 4. Card Selection Visual Feedback
- **Highlight Style**: Blue border (3px solid #667eea)
- **Duration**: While modal is open or session running
- **Effect**: Makes active todo visually distinct
- **Auto-Remove**: When modal closes or session ends

#### 5. Floating Badge (Background Indicator)
- **Position**: Fixed bottom-right (30px from edges)
- **Style**: Gradient background (purple #667eea to #764ba2)
- **Content**: Play icon + Timer display
- **Appearance**: 
  - White text on gradient
  - Box shadow for depth
  - 50px border-radius (pill shape)
  - Clickable to return to modal
- **Display**: Only shown when session running
- **Behavior**: Updates timer independently every 1 second

#### 6. Modal Close Behavior
- **User Closes Modal**: Auto-pauses session
- **Background Behavior**: Floating badge continues showing active session
- **Timer**: Continues counting in background
- **Re-open**: Click floating badge to return to modal

#### 7. End Session Behavior
- **Button Click**: /done API call triggered
- **Result**: Modal closes, card highlight removed, floating badge removed
- **Page Reload**: Yes - to refresh todo list
- **User Experience**: Clean completion flow

### API Integration
Uses existing endpoints (already implemented):
- `POST /<todo_id>/start` - Start work session
- `POST /<todo_id>/pause` - Pause work session
- `POST /<todo_id>/resume` - Resume work session
- `POST /<todo_id>/done` - Mark todo as done

## Implementation Notes

### Key Design Decisions

1. **Modal Over Inline Buttons**
   - Provides focused UI for work session
   - Reduces clutter on todo cards
   - Better mobile experience

2. **Card Click for Selection**
   - More intuitive than separate checkbox
   - Blue border provides visual feedback
   - No additional HTML elements needed

3. **Floating Badge**
   - Non-intrusive background indicator
   - Allows continued browsing while session active
   - Fixed position doesn't interfere with scrolling

4. **Auto-Pause on Modal Close**
   - Prevents unintended work session accumulation
   - User can resume when ready
   - Respects user intent

5. **Page Reload on Mark Done**
   - Ensures todo list stays in sync
   - Removes todo from view immediately
   - Best practice for todo apps

### Known Limitations
- Modal only visible on /today and /tomorrow (by design)
- One active work session at a time (matches product intent)
- Timer resets if page is reloaded while session running (can be enhanced)
